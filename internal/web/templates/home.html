Un CV que les ATS lisent, et que le recruteur finit.

atscv décrit votre CV une seule fois, dans un fichier JSON, puis le rend en DOCX, PDF, AsciiDoc et texte brut. Les quatre sorties partagent le même flux de blocs : ce qu’un parser extrait du PDF, il l’extrait aussi du DOCX, dans le même ordre.

Un CV est un document, pas une page blanche

Un parser ne lit pas une mise en page : il lit des blocs de texte, dans l’ordre. Tout ce qui n’est pas du texte — une image de mise en page, un tableau à deux colonnes, une zone de texte, un PDF dont les glyphes sont des dessins — disparaît ou perd sa place. atscv ne produit que la première catégorie.

Une seule colonne

Le parcours de lecture d’un parser suit l’ordre du flux. Une colonne, c’est cet ordre-là, et rien d’autre à deviner.

Du texte, pas des images

Le DOCX comme le PDF contiennent des caractères, pas des dessins. Un `.docx` est un ZIP d’XML, un PDF une page de glyphes indexés : les deux s’extraient.

Le même ordre partout

Les quatre renderers partagent le même modèle de blocs, donc le même ordre de lecture. Le PDF ne réordonne pas ce que le DOCX a sequencé.

Rien ne disparaît

Pas de pied de page, pas de numéro, pas de texte alternatif qui porterait seul une information. Tout ce qui est écrit est dans le flux.

Trois étapes, et rien à installer pour essayer

  1. Décrire

    Un JSON strict : un champ inconnu est rejeté, pas ignoré. Une typo dans une clé échoue tout de suite, au lieu de disparaître du CV. L’éditeur web construit ce JSON pour vous, section par section.

  2. Vérifier

    atscv lint note ce qu’un parser perd ou ce qui coûte des points, et atscv check sort en erreur dès qu’une information se perd. Les deux sont faits pour une CI.

  3. Exporter

    Un JSON, quatre fichiers. Le .docx pour l’envoi, le .pdf pour l’archive, l’AsciiDoc pour la version web, le .txt pour vérifier soi-même ce qu’un ATS lit.

Ce que perd un parser, écrit noir sur blanc

Le linter n’est pas un correcteur de style. Il porte sur ce qui disparaît à l’extraction, et sur ce qui coûte un point à une recherche par mot-clé.

$ atscv lint -i data/resume.demo.json
warning dates.start            activities[0]      the period has no start date
        → an undated entry is invisible to a chronological filter

readability 71/100 | ~1 page(s) | 232 words | 4 entries | 6 achievement lines, 5 with a figure | 10 skills
  • error l’information sera perdue ou illisible à l’extraction ; la commande sort en 1.
  • warning un filtre, une recherche par mot-clé ou un recruteur perdra un point.
  • info une suggestion, pas un défaut.

La pagination se mesure, elle ne s’espère pas

Un CV qui déborde sur une deuxième page n’est pas un problème de mise en page, et personne ne le signale à votre place. atscv fait tourner le vrai moteur, avec la vraie police, avant de compter.

  • Un titre de rubrique ne reste jamais seul en bas de page : le titre, son filet et la première ligne vont ensemble.
  • Une entrée qui tient sur une page y reste entière ; une expérience, une formation, une activité ne se coupent pas en deux.
  • Une entrée plus haute qu’une page se coupe quand même, mais son titre, ses dates et la première ligne de son corps restent ensemble.
$ atscv check -i data/resume.demo.json
ok: 232 words, 4 entries, 10 skills, 1 page

Le .docx applique les mêmes trois règles avec les propriétés de paragraphe que Word comprend : keepNext sur les titres et le corps de chaque entrée, keepLines sur les titres. Quand une entrée dépasse la hauteur d’une page, Word ignore keepNext et coupe là où il peut, comme le PDF.

L’éditeur, servi par le binaire lui-même

Chez vous, sur votre machine

atscv serve n’écoute que sur le loopback : une adresse publique est refusée au démarrage. Vos sessions vivent dans le localStorage du navigateur, le serveur ne garde rien.

Sans compte et sans tiers

Aucune inscription, aucun envoi, aucune police distante : htmx est embarqué dans le binaire et la politique de sécurité interdit tout ce qui sort du serveur, styles et scripts compris.

Aperçu, diagnostic, texte brut

Trois vues sur le même contenu : le rendu, le rapport du linter, et l’ordre de lecture qu’un parser extrait. Les trois se mettent à jour à la frappe.

Import et export

Un JSON entre, un JSON sort ; les quatre formats se téléchargent depuis la même page. Vos données restent un fichier que vous détenez.

Les quatre formats produits par atscv et leur usage
FormatPour quoi
.docxL’envoi à un recruteur ; Word est le moteur ATS le plus courant.
.pdfL’archive, et le rendu que l’on veut voir avant d’envoyer.
.adocLa version web, versionnable dans un dépôt.
.txtLa vérité : l’ordre de lecture brut, sans mise en forme.

Installation

$ cd atscv
$ go build -o atscv .
$ ./atscv check -i data/resume.demo.json
ok: 232 words, 4 entries, 10 skills, 1 page

Ensuite :

# Les trois formats principaux, dans un répertoire
$ ./atscv build -i data/resume.demo.json -o dist/

# L’éditeur web, sur le loopback
$ ./atscv serve

Les sorties montrées sur cette page sont celles de data/resume.demo.json, un CV fictif livré avec le dépôt : elles sont produites par la commande, pas écrites à la main, et un test vérifie qu’elles correspondent toujours à la sortie réelle.
